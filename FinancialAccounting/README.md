# **Учёт финансов**

## **1. Общая идея решения**

Приложение предназначено для учёта финансовых операций. Основные сущности:

●     **BankAccount** – банковский счёт, содержащий уникальный идентификатор, название и текущий баланс.

●     **Category** – категория операции (доход или расход) с названием.

●     **Operation** – финансовая операция, которая включает сумму, дату, тип (доход/расход) и ссылки на счёт и категорию.

Пользователь взаимодействует с приложением через консольное меню, где он может создавать и просматривать счета, категории и операции, а также выполнять удаление записей, импортировать/экспортировать данные в формате CSV и JSON.

## **2. Архитектура и структура решения**

Проект разделён на несколько модулей:

●     **Domain** – доменные классы: BankAccount, Category, Operation.

●     **Factories** – централизованное создание объектов через класс FinancialFactory (реализует фабричный паттерн).

●     **Facades** – фасады для управления сущностями:
	- BankAccountFacade (работа со счетами, с использованием репозитория и прокси)
	- CategoryFacade (работа с категориями)
	- OperationFacade (работа с операциями, автоматическое изменение баланса)
	- AnalyticsFacade (агрегация данных, например, суммарный баланс, сумма доходов/расходов).

●     **Repositories** – репозитории для хранения данных (в примере используется InMemoryBankAccountRepository и его прокси BankAccountRepositoryProxy).

●     **Importers/Exporters** – для импорта и экспорта данных реализованы:
	- **JsonImporter** и **CsvImporter** (паттерн «Шаблонный метод»),
	- **JsonExportVisitor** и **CsvExportVisitor** (паттерн «Посетитель»),
	- **ExporterService** объединяет логику экспорта.

●     **Commands** – пример использования паттерна «Команда» с декоратором TimingCommandDecorator для замера времени выполнения команд.

●     **Console** **Interface** – консольное меню в Program.cs для интерактивной работы с системой.

## **3. Реализованные паттерны** **GoF** **и дополнительные паттерны**

1. **Factory (Фабрика):**
- Реализовано в классе FinancialFactory (интерфейсы IBankAccountFactory, ICategoryFactory, IOperationFactory). Централизует создание доменных объектов и их валидацию.

2. **Facade (Фасад):**
- Модули BankAccountFacade, CategoryFacade и OperationFacade предоставляют упрощённый интерфейс для работы с группами сущностей, инкапсулируя бизнес-логику.

3. **Proxy (Прокси):**
- Класс BankAccountRepositoryProxy обеспечивает кэширование и синхронизацию с базовым репозиторием (в примере – in-memory).

4. **Template Method (Шаблонный метод):**
- Импортеры JsonImporter и CsvImporter наследуются от абстрактного класса BaseImporter, реализующего общий алгоритм импорта (чтение файла, парсинг, создание объектов).

5. **Visitor (Посетитель):**
- Экспорт данных реализован через посетителей JsonExportVisitor и CsvExportVisitor, которые обходят объекты и формируют итоговую строку (JSON или CSV).

6. **Command + Decorator:**
- Пример команды создания счёта CreateAccountCommand обёрнут в TimingCommandDecorator для замера времени выполнения.

## **4. Принципы SOLID и GRASP**

●     **SRP** **(Принцип единственной ответственности):** Каждая сущность (доменные классы, фасады, импортеры, экспортеры) отвечает только за свою задачу. Например, BankAccountFacade отвечает исключительно за управление счетами.

●     **OCP** **(Принцип открытости/закрытости):** Новые типы операций или расширение функционала возможно путём добавления новых классов (например, новый импортёр или экспортер) без изменения уже существующего кода.

●     **LSP** **(Принцип подстановки Барбары Лисков):** Классы реализуют интерфейсы (например, фабрики, репозитории), что позволяет подставлять альтернативные реализации (например, для тестирования).

●     **ISP** **(Принцип разделения интерфейса):** Интерфейсы разбиты на специализированные (например, IBankAccountFactory, ICategoryFactory), что снижает зависимость модулей от ненужных методов. 

●     **DIP** **(Принцип инверсии зависимостей):** Фасады и высокоуровневые модули зависят от абстракций (интерфейсов фабрик и репозиториев), а не от конкретных реализаций.

●     **GRASP (General Responsibility Assignment Software Patterns):**

- **Controller:** Фасады выступают в роли контроллеров, управляя операциями над доменными объектами.
- **High** **Cohesion** **и Low** **Coupling:** Каждый модуль отвечает за строго определённую задачу, что упрощает поддержку и развитие системы.

## **5. Особенности реализации экспорта и импорта данных**

### **Экспорт в** **JSON**

Экспорт реализован через класс JsonExportVisitor, который записывает каждый объект вертикально с отступами и запятыми, формируя корректный JSON-массив. Пример результата:

```JSON
[
  { "type": "BankAccount", "id": "15d352dd-6890-4ac7-89e0-7d51fecb88c3", "name": "мой", "balance": 149900 },
  { "type": "Category", "id": "e9331137-4e31-4f3f-8c81-73f5aafe8839", "name": "Кафе", "opType": "Expense" },
  { "type": "Category", "id": "30b73775-ba00-4448-8fb5-872fb51a546a", "name": "ЗП", "opType": "Income" },
  { "type": "Operation", "id": "a674dcb1-c848-4b24-bd8f-79f695e89c06", "opType": "Income", "amount": 50000 },
  { "type": "Operation", "id": "ad07018f-8a03-4bc6-8233-c3c018b2f9e7", "opType": "Expense", "amount": 100 }
]
```

Импорт из JSON реализован в классе JsonImporter так, что корневой элемент должен быть массивом объектов. В зависимости от значения поля "type" создаются соответствующие сущности через методы импорта фасадов (с сохранением исходных ID).

### **Экспорт в** **CSV**

Экспорт в CSV выполняется через CsvExportVisitor и формирует строки в формате:

●     **Account:** Account;ID;Имя;Баланс

●     **Category:** Category;ID;Тип;Имя

●     **Operation:** Operation;ID;Тип;Сумма;Дата;AccountID;CategoryID;Описание

Импорт из CSV реализован в CsvImporter с ожиданием указанного формата.

## **6. Инструкция по запуску**

1. Перенесите проект на компьютер
2. В корне проекта создайте файлы для импорта:
	- **demo.csv** – файл с данными в формате CSV (как указано выше).
	- **demo.json** – при необходимости, файл с экспортированными данными в формате JSON.
3. Постройте и запустите проект:  
    dotnet build
    dotnet run
4. В консоли появится меню, позволяющее:
	- Создавать, просматривать и удалять счета, категории и операции.
	- Выполнять экспорт данных в JSON и CSV (результат записывается в файлы export.json и export.csv).
	- Импортировать данные из файлов demo.json и demo.csv.
5. Следуйте инструкциям меню для проверки работы приложения.
